# Download the app, push notifications, the icon badge

> Moved verbatim from CLAUDE.md "Key Conventions" on Oct 13 2026. Convention numbers are kept because code comments and docs cite them. Read the devlog entries each convention names (`docs/devlog.md`) before changing the code it describes.

## Convention 31 — The app is DOWNLOADED from the browser, never a store; one rule says what a device can do ("Download the app", Oct 2 2026, zero DDL)

**The app is DOWNLOADED from the browser, never a store; one rule says what a device can do ("Download the app", Oct 2 2026, zero DDL)** — Tom: an icon on the phone that opens Edge Athlete like any app, every feature, no App Store or Google Play (the store apps stay on the roadmap, `docs/ROADMAP_2026-10.md`). The manifest (`src/app/manifest.webmanifest/route.ts`, `id: '/feed'` explicit so a changed start page never forks installs) already made it possible; this made it visible. `src/lib/install/platform.ts installMode` (pure, zero imports) is THE rule: `installed` (running from the icon) · `prompt` (Android / desktop Chromium handed over `beforeinstallprompt` — one tap) · `ios-safari` · `ios-browser` · `ios-in-app` / `android-in-app` (another app's browser cannot add to a home screen) · `android-menu` · `desktop`. The limits are Apple's and Google's and the copy says them plainly: **an iPhone has no install API — it is Share → Add to Home Screen → Add**, and an installed iPhone app keeps its own sign-in. `src/lib/install/store.ts` holds the live signals (wired when the module loads — the prompt event fires once, early; every API feature-checked for the iOS 15 floor; `ea:app-installed:v1` lets a browser tab on the same device stop inviting) and `InstallAppProvider` (root-mounted beside the Edit Profile host; `useInstallApp()` → `canInvite`, `install()`, `openGuide()`) reads it through `useSyncExternalStore`. Doors, all gone once installed: "Get the app" in the header dropdown AND the drawer, Settings → Account, the feed's `InstallCard` (phones and tablets, dismissed for good, never beside the Get Started card — a sibling rule in `globals.css`), and the sign-in page. **There is NO service worker** — installing needs none; offline and push are their own rounds, and a worker needs `worker-src 'self'` in `buildCsp` first (script-src carries `'strict-dynamic'`, so `'self'` does not cover it). A real install cannot be automated: `e2e/install-app.spec.ts` plays each device state (a user agent, a synthetic prompt event, `navigator.standalone`); Tom's phone is the proof.
**Phone notifications + the icon's number (Oct 2 2026, mig 248 — `docs/PUSH.md`):**
- The worker exists now: `public/sw.js`, **push + notificationclick, plus ONE cache** (speed round 2, Oct 4 2026): registered as `/sw.js?static=1` when `NEXT_PUBLIC_SW_STATIC_CACHE=1` (build-injected; ON in production since Tom's iPhone passed the gate), it answers GET `/_next/static/*` — hashed, immutable — cache-first and NOTHING else (documents, `/api/*`, images pass through; no offline mode, no stale page). `src/lib/sw/static-cache.ts` is the rule; `swUrl` is the ONE worker URL the push opt-in and the boot registrar share. Playwright WebKit stalls under any fetch handler (`sw-static-cache.spec` is `fixme` there) — a real iPhone does not. `buildCsp` carries `worker-src 'self'`.
- **The icon's number IS the bell's unread count.** A DM is already a `new_message` row, so it counts once. **Opening the bell or the Notifications screen IS seeing it (Tom, Oct 4 2026):** everything is marked read on open — the dot and the icon's number go to zero together; the rows new at that moment keep the "new" look for that open (`freshIds`); there is no Unread tab and no "Mark all read" button. A read conversation clears its `new_message` bells (`/api/messages/[id]/read`), a decided fan request is a read bell, a return to the foreground re-reads the list (20 s gap), and anything read in the app is CLOSED on the phone's notification center (`closeShownNotifications` — by the worker's `data.id` / `tag`).
- **The ONE sender** is the every-minute sweep (`src/lib/push/sweep-server.ts`, pg_cron `push-sweep` → `POST /api/push/sweep`). It claims rows by stamping `notifications.pushed_at` before sending. No notification writer knows about phones — never add a push call to a writer.
- A tap opens the row's own `action_url` (through `safeAppPath`).
- **Per DEVICE:** `push_subscriptions`. The permission is asked only from a tap (iOS ignores anything else); an iPhone does it only in the home-screen app.
- Sign-out turns the device off first. Without the VAPID keys no door shows.
- **The feed card asks ONCE per device per account (Oct 4 2026):** the CHOICE is remembered on the device (`ea:push:device-choice:v1`, keyed by account — `src/lib/push/card.ts cardDecision` is the one rule); either answer hides the card for good and Settings is the door. A device that chose ON but holds no subscription (a sign-out turned it off; iOS dropped it) is repaired SILENTLY at boot (`syncPush(userId)`, one run per account per page load; granted permission needs no gesture to subscribe) — never asked again. Never derive "on" from the live subscription alone: that was the bug.
