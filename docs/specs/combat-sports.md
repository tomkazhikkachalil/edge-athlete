# Combat sports: bouts with results

## Convention 44 — MMA, boxing, wrestling and jiu-jitsu are sports, and a bout is a result (Oct 16 2026, activities details C1–C3, zero DDL)

Tom (Oct 15): combat sports are SPORTS with real results, not only a training activity. The `martial_arts` activity stays the training record (drilling, sparring, class — its Finish asks discipline, session, sparring rounds, belt) and is never bridged to a result.

- **Four registry sports, as data** (`mma`, `boxing`, `wrestling`, `bjj` "Jiu-Jitsu"): registry entry, stat-line adapter, `FEATURE_SPORTS`, stat schema, settings schema, equipment categories, brands and specs, badges, tag lists. `registry-agreement.test.ts` pins the registry's enabled set ≡ `FEATURE_SPORTS`, each with an adapter and (but golf) a stat schema.
- **The bout** (`src/lib/sports/bout.ts`, pure, zero imports) rides on the stat line as `bout` beside the numeric `stats`: `result` W · L · D · NC; `method` — the sport's own (`BOUT_METHODS_BY_SPORT`: KO, TKO, submission, unanimous / split / majority decision, doctor stoppage, RTD, pin, technical fall, major decision, forfeit, injury default, points, advantages, referee decision, DQ), each flagged `finish` (ended early) or `distance` (went the distance); `round` and `time_s` only when it did not go the distance, within the rounds scheduled and the round's length; `context` — weight class, rounds × minutes scheduled, and the sport's own (`BOUT_CONTEXT_BY_SPORT`: amateur / pro for MMA and boxing, folkstyle / freestyle / Greco-Roman for wrestling, gi / no-gi and belt for jiu-jitsu). `validateBout` refuses by name; unknown keys are refused.
- **The envelope's W / L / T is DERIVED on the server** (`envelopeResult`): a draw is T, a no contest has NO result — never a win. A client's result that disagrees with its bout is a 400. The posts route stores the checked line. Every existing reader (first-win badge, share card, cards) keeps reading W / L / T unchanged.
- **A bout alone is a complete line** — its numbers (strikes, takedowns, sweeps …, all optional) are not required, and the performance row is written with empty metrics when there is a bout.
- **No outcome, no DDL:** a self-posted bout's opponent is free text, not a shared game, so `athlete_performances.outcome` stays NULL (244: an outcome needs a `context_key`); the bout lives in the row's `context`. Rivalries pair two ATHLETES who share a game, so a typed opponent forms none — a bout between two athletes on the platform is a later program (a bout as an event).
- **Profile:** tile kinds `record` ("3-1-1 (1 NC)") and `finishes` (wins that ended early) read the lines' bouts; the recent-activity column reads the bout headline. **Badges:** `first_win` as for every sport; `first_finish` (a `finish` rule — a W whose method ends early). A no contest earns neither.
- **Composer:** `BoutFields` replaces the W / L / T buttons for the four (Win / Loss / Draw / No contest, ≥ 44 px; how it ended; round and time only for an early ending; weight class; rounds × minutes; the sport's own chips). **Feed:** a post with a bout renders `StatLineCard` — the result pill and the headline without the result ("TKO · R2 1:47 · Pro · 155 lb").
