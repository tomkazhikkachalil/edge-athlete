# Contacts and the admin console

> The flow changes program, Oct 19 2026 (items 1 and 2 of Tom's list). Convention 47 is the contact list; Convention 48 (the admin console's own door) lands with program B. Read the devlog entries of Oct 19 2026 (Flow changes A1–A3) before changing any of it.

## Convention 47 — A sign-up or inquiry is a contact row, a mail to ONE setting, and a confirmation the person reads (migration 266, #1231–#1233)

Tom: *"When someone signs up for notifications or sends an inquiry, nothing happens with it right now."*

- **The row.** `contacts` (266) holds one row per submission — `email` (lowercased), `name`, `source` (`notify_signup | inquiry`), `message`, `marketing_consent`, `consent_text` (the exact words the checkbox showed — CASL wants express consent, recorded), `user_type`, `created_at`. RLS on, NO policies: service-role only (the 027 posture; these are addresses of people who are not users). The list keeps history; the export dedupes. The 027 `waitlist` rows were copied in with consent false; `waitlist` is history, never written again.
- **ONE writer:** `src/lib/contacts/contacts-server.ts recordContact` — the row, then a best-effort mail. A repeat from the same address and source inside 24 h (`REPEAT_MAIL_WINDOW_MS`) is a row but no second mail. A failed mail is Sentry's, never the visitor's: the request still answers 201.
- **ONE door:** `POST /api/contacts` — public (the coming-soon page is signed out); the guest ticket's posture: a `website` honeypot (a bot's "success", nothing stored), the `contacts` IP bucket (5 / h), bounded text, an inquiry needs a message. Pre-266 a 503 by name. `/api/waitlist` is gone (A2).
- **ONE setting:** the mail goes to `app_settings.notify_inbox_email` (266; edited on the console's inbox card through `PUT /api/admin/settings`, a key from `APP_SETTING_KEYS` only) — then `CONTACT_EMAIL`, then `EMAIL_FROM`. Never a hardcoded address. `notifyInboxAddress` caches a minute; the write clears it. SMTP unset = the row is kept and the mail skipped. "Send a test email" (`POST /api/admin/contacts/test-mail`) answers honestly (`smtp_unset` · `no_address` · `provider_refused`), never a 500 for a mail that did not go.
- **The mail:** `emailService.sendContactNotification` through `deliver()`, Reply-To the visitor, subject "New sign-up: {name or email}" / "New inquiry: …", a plain-text body of the five facts (name, email, date, source, consent) and the message.
- **The forms** (A2): the coming-soon page (`ComingSoon.tsx`) — Notify me takes an optional name and an UNTICKED consent box; "Have a question? Send us a note" turns it into an inquiry with a required message; the confirmation replaces the form (`role="status"`, names the person and the address) and the sign-in door stays under it. The landing popup (`WaitlistPopup`) takes the same fields. The consent sentence is ONE string — `COPY.CONTACTS.CONSENT_LABEL` ≡ `MARKETING_CONSENT_TEXT`, pinned by test — and travels with the row as `consent_text`.
- **The console** (A3): `/dashboard/contacts` (→ `/admin/contacts` with program B) — the inbox card, then the list (`ContactsPanel`: source / consent / search filters, 50 a page, a tap opens the message) and two downloads from `GET /api/admin/contacts/export`: `?list=all` (every submission) and `?list=marketing` (the consented addresses, one per email — `marketingList`: the LATEST submission that showed the checkbox decides). The CSV is RFC 4180 and **formula-safe** (`csvEscape` prefixes `= + - @` tab CR with `'`). Past 10,000 rows the file's last line says it is a floor. A Contacts tile with the counts sits beside the Support queue tile.
- **Pinned by:** `src/lib/__tests__/contacts.test.ts` (the CSV, the dedupe and consent rules, the repeat window, the subject and body, the migration's sources and RLS, the consent sentence), `e2e/contacts-api.spec.ts`, `e2e/coming-soon.spec.ts`, `e2e/admin-contacts.spec.ts` (admin-positive; skips without `E2E_ADMIN_EMAIL`).
